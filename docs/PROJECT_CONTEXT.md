# HarmonicaPlayer 项目上下文

## 1. 项目定位

当前范围以本文末尾“v0.5.0发布授权与范围”、2026-10-12功能规则及 docs/NEXT_UPDATE.md 顶部为准。v0.4.0严格导入、播放列表暂缓等旧日期条目保留作历史。

HarmonicaPlayer 是一个为《三角洲行动》口琴演奏场景制作的 Windows 自动演奏工具。

项目最初从简单 TXT 简谱自动按键演奏开始，逐步发展为包含：

- 曲谱解析
- 节奏控制
- 本地试听
- 进度显示
- MIDI 导出
- 内置口琴采样
- 快捷键与停止控制
- 错误提示
- 发布与测试流程

的完整小型桌面工具。

当前正式版本基线为：

**HarmonicaPlayer v0.5.0**

## 4. 当前谱面系统

TXT 是项目主要的曲谱输入、编辑和分享格式。

### 音区

- 中音：`1` ～ `7`
- 高音：`【1】` ～ `【7】`
- 低音：`（1）` ～ `（7）`
- 双层仅最高do：`【【1】】`及v0.4.0新增的升半音`【【#1】】`；不支持双层2～7，包括升半音
- 中音、低音、高音1～7均可升半音，包含`#3`、`#7`；v0.4.0兼容全角`＃`，新输出推荐半角`#`

### 时值

1 拍 = 四分音符。

- `5` = 1 拍
- `5_` = 0.5 拍
- `5__` = 0.25 拍
- `5.` = 1.5 拍
- `5_.` = 0.75 拍
- `5:1.25` = 自定义 1.25 拍
- `5 —` = 额外延长 1 拍

### 休止

- `0`
- `0_`
- `0 —`
- `0:0.25`

### 语义原则

- 空格用于分隔，不应自动产生额外停顿
- 相同音高且有延音关系时，可以按规则合并时值
- 不同音高的连奏不能直接合并
- 重复同音若没有延音关系，不应自动合并
- 无法确认的谱面不应自动“猜测补齐”

## 5. 播放系统的核心概念

历史上项目同时存在：

- 实际游戏演奏
- 本地声音试听
- 播放进度
- 当前音符位置
- MIDI 导出

这些功能应尽可能共享一致的节奏解释。

重点参数：

- BPM
- 音符时值
- gap / 音符间隔
- 休止
- 播放起点
- 停止 / 取消

若这些模块分别有独立计算逻辑，应重点检查是否存在重复实现和行为偏差。

不要为了代码复用而立即进行大规模重构；首次扫描只需要指出风险。

## 6. 音频系统

当前版本使用内置真实口琴采样进行本地试听。

历史上最初的合成音效果较差，因此改为真实采样方向。

曾出现的典型问题：

某些连续音，例如：

```text
【3】 【2_】 【1】 【2_】
【3_.】 【4__】 【3_】 【2.】
```

可能出现类似“突突突”的尾音杂音或重复感。

后续版本已经进行过优化。

Codex 修改音频逻辑时，应关注：

- sample 尾部
- 循环点
- stop 时机
- 重复触发
- 相邻音重叠
- fade
- 短音切断
- 同音连续播放

## 7. MIDI 导出

MIDI 导出在 v0.3.x 中加入。

当前产品预期是：

标准单轨 MIDI，并尽量保留：

- 音高
- BPM
- 音长
- 音符间隔
- 休止

MIDI 是输出能力，不代表当前要将内部系统全面迁移到 MIDI。

## 8. 快捷键和紧急停止

快捷键是项目历史上较容易出现问题的区域。

已知历史问题包括：

- 紧急停止快捷键偶尔不稳定
- 快捷键冲突
- 倒计时期间状态问题
- 停止后残留播放
- 开始 / 停止异常

未来修改此区域时应优先保证：

- 停止动作始终可用
- 停止不会被播放线程阻塞
- 不产生多个并行播放任务
- 应用退出可以清理后台状态

## 9. 设置保存与异步

外部贡献中曾涉及设置保存竞态问题。

问题核心：

旧保存请求可能在等待 / 写盘过程中晚于新请求完成，导致旧值覆盖新值或 UI 状态回退。

因此当前异步设置逻辑应检查：

- 请求顺序
- 最新状态判断
- UI 更新
- 写入串行化
- 失败重试
- CancellationToken
- 程序退出行为

Codex 首次扫描时应确认当前实现是否已经包含对应防护。
